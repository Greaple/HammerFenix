# Roadmap

Goal: near-perfect clone of Hammerfest. Each task is sized for about one conversation. Tick boxes as work lands.

## Next up

The UI and UX polish batches U.1 to U.4 are done (section below); left there: English and Spanish title logos, and a check of the phone layouts on a real device. Phases 1, 2 and 3 are done. Phase 3 (the site screens, quests and profile, game options and localization; see PORT_STATUS.md "Site screens", "Quests and profile", "Game options" and "Localization (3.4)") was done before Phase 2B. Next is Phase 2B, starting with the automated data pass and the level jump for Ruffle (2B.0), then the small dimensions (2B.12) and the Adventure batches (2B.1 to 2B.11); the larger dimensions (2B.13 to 2B.28) come with Phase 4 (see "Order" in Phase 2B). For 2B comparisons, start games from the debug toolbar: they use the no-site families and no options, as the Ruffle side-by-side does. The bosses' look in Ruffle (Bat glow, exit arrow during the fights) is left for 2B.11. Level changes now take 57 frames (IA parse + scroll) and a new game 17, so tests that start a level must step past that. After any behavior fix, check the replay snapshot diff and accept it with `npx vitest run -u`. Open deviations from the audits are listed in PORT_STATUS.md ("Audit 1.5" to "Audit 1.7"). Phase 5 (polish) is done: audio (5.1), performance and mobile (5.2), offline play (5.3); none of it is tried on a real phone yet. A settings page for the site's "Paramètres" (`$volume`, `$sound`, `$music`, `$detail`, `$shake`) is still missing; the volumes in `GameParameters` take it as an argument.

## Bugs (found in play)

Logged during play, not yet investigated in depth. Check each against the Ruffle side-by-side before fixing.

- [ ] Shield animation seems to loop (invincibility after losing a life, or from an item). `Player.shield()` and `onShieldOut()` in `src/game/entity/Player.ts` match the original (`hammer/entity/Player.mt` `shield()`, which also sets `shieldMC.fl_loop = true`), so first compare with Ruffle. If the original only plays an intro once, look at the `hammer_player_shield` symbol's timeline (frame scripts, `stop()`) and at how `FxAnim` handles `fl_loop` and `lifeTimer`.
- [x] Fixed in 3.4 (the screen) and the UI batch U.1 (its music volume). Pause screen (P key) flickers fast between two frames of `hammer_interf_instructions`: the controls page and a "time label 999:00" page (the time attack page). Every text shows its placeholder ("Title Label", "moveLabel", "SPACE LABEL", "click label", "Sector label"), and the tip shows raw `<p><font …>tips...</font></p>` HTML. Compare `GameSession.onPause()` (`src/game/GameSession.ts`) with `mode/GameMode.mt` `onPause()`:
  - The port never calls `pauseMC.gotoAndStop("1")`, so the clip plays through its frames.
  - Texts not set: `click` (to `""`), `pause` (Lang 9), `space` (Lang 10). `sector` is missing the Lang 14 prefix. `title`, `move` and `attack` still show placeholders, so either `getText` doesn't find the fields or `dataStore.getStatic()` returns nothing; the port's English fallbacks (`'PAUSE'`, `'Move: Arrows / WASD'`...) are invented and should go.
  - Tip: the original sets `tip.html = true` and `htmlText = "<b>" + Lang 300 + "</b>" + tip`, cycling `tipId` through Lang 301+ until one is missing. The port writes plain text and always uses 301. Needs HTML text support in the SWF text field (or check if it exists) and a `tipId` field on the session.
  - The original also sets the music volume to 0.5 when not muted; check `onUnpause()` restores it.

## Phase 5: Polish

- [x] 5.1 Audio mix parity (channels, priorities, music switching). Done: `src/engine/Audio.ts` is now a port of `mtypes`' `SoundManager` (from github.com/motion-twin/mtypes). Sounds on a channel overlap instead of cutting each other (Flash `Sound.start`), each channel has its own volume as `GameManager` sets them (enemies and interface 10 lower), at most 32 sounds at once, the music at the original's level (0.65 of the sounds', `Mode.setMusicVolume` rounding) and restarted when asked again. There are no priorities in the original. The volumes use the site's default settings, as no settings page exists yet. Sounds are fetched at start and decoded on the first gesture, so the first of each no longer plays late. Tested in `tests/audio.test.ts`. See PORT_STATUS.md "Engine".
- [x] 5.2 Performance and mobile pass. Measured on a Mac: a logic tick costs 0.12 ms and a render 0.5 ms (about 370 display objects on a level), so the game itself is light. Done: the page renders only when the game stepped (32 Hz) instead of at every screen refresh (60 or 120 Hz on phones), except while a site screen, a fade or a stopped loop shows (`main.ts`, `FixedGameLoop.stepCount`). Bug fixed: a page opened in a hidden tab stayed on the loading screen, as `Shell.load` waited on `img.decode()`, which Chrome fails or never settles there; it now waits for `load`. Touch: the buttons no longer let a moving thumb scroll, zoom or pull to refresh (`touch-action: none`, `overscroll-behavior: none`), which cancelled the press; the D-pad follows the finger from arrow to arrow, and keeps its arrow when the thumb drifts off. Checked: the touch buttons and their blur never cover the game in either orientation. Left as is: vector shapes are drawn into textures on first use (0.13 ms each on average, 14 ms at worst, so a short hitch on a slow phone when a large one first shows), and `library.json` is 9 MB (2.7 MB gzipped, mostly path data). Not yet tried on a real phone.
- [x] 5.3 Offline play (PWA). Done: the build writes a service worker (`tools/vite-plugin-offline.ts`, `sw.js`) that caches all 307 files of the build (about 17.7 MB; not the Ruffle side-by-side or the source maps) once the game has loaded, and serves them first, so the game starts and plays with no network; the dev server never registers it. Its cache is named from a hash of the files, so a deploy that changes a file replaces the cache, and an unchanged build keeps it (the font builder now writes fixed timestamps, `fixTimestamps` in `tools/build-fonts.ts`, which made every build different). A manifest (`public/manifest.webmanifest`) and icons make it installable; the icons are the hammerfest.fr site's own favicon, a 16 x 16 ice cube, scaled pixel for pixel (`tools/build-icons.ts`, `public/icons/`). This also fixes the favicon, which pointed at a missing file. Tested in `tests/offline.test.ts`, and in the browser with the build served by the "preview" launch config, then the server stopped: the page reloads, a game starts, another level set loads and the sounds are there.
